# HASLA 모바일 리플렛 — 디자인 스펙 (교체용 자산 규격)

**문서 대상:** 이 사이트의 이미지·지도·로고·티저 영상을 새로 만들거나 교체할 디자이너
**함께 볼 문서:** [`HANDOFF.md`](../HANDOFF.md) — 담당자용 파일 교체 절차
**서비스 주소:** https://hasla-gangneung.vercel.app
**마지막 업데이트:** 2026-07-07 (지도·아이콘 재디자인 반영)

---

## 이 문서를 쓰는 이유

새로 받은 파일이 **파일명·확장자·비율·투명도 규칙만 맞으면** 담당자가 GitHub 웹에서 파일을 통째로 교체하는 것만으로 즉시 반영됩니다. 이 규칙을 벗어나면 잘림·왜곡·배포 실패가 발생하니 아래 스펙을 반드시 지켜주세요.

**공통 원칙 4가지**
1. **파일명은 소문자·영문·언더스코어(`_`)·하이픈(`-`)** 조합만. 한글·공백·특수문자 금지.
2. **확장자를 유지** — `.png` 자리에 `.jpg`를 넣으면 안 보입니다. 확장자를 바꿔야 한다면 개발자 요청서에 명시.
3. **비율(Aspect ratio)을 지켜야 크롭 없이 표시됨** — 각 항목별 목표 비율은 아래 표 참고.
4. **최종 납품 파일은 항상 PNG/JPG/MP4**. AI·PSD는 필요 시 참고용으로 함께 주시되, 웹용 파일이 반드시 있어야 합니다.

## 1. 지도 배경 이미지

**파일:** `public/images/map.jpg`
**형식:** JPG (RGB)
**정확한 크기:** **1600 × 2100 px**
**정확한 비율:** **1600 : 2100 = 0.7619 (세로형)**

### 절대 지켜야 할 것

- **비율(1600:2100) 이 바뀌면 지도 위 존 아이콘들이 어긋납니다.** 존 아이콘 위치는 지도 이미지의 % 좌표로 계산되므로, 비율이 달라지면 모든 좌표(8개)를 개발자가 재조정해야 합니다.
- 지도 컨테이너는 코드에 `aspect-[1600/2100]` 로 하드코딩되어 있음. 다른 비율로 지도를 제작하려면 반드시 개발자에게 미리 알려주세요.
- **크기(픽셀 수)** 는 1600 × 2100 을 유지하되, 그 이상 크기(예: 3200 × 4200)도 무방합니다. 단, 비율만은 정확히 유지.

### 권장 사항

- **어두운 야간 톤** — 사이트 전체가 다크 UI (배경 `#0F1320` 계열). 지도 배경이 밝으면 화면에서 튀어보임.
- **파일 용량** — 3MB 이하 권장. 5MB 초과 시 모바일 초기 로딩이 느려짐.
- **DPI/해상도** — 웹용이므로 72 DPI로 충분. 인쇄용 300 DPI는 파일만 커지고 이득 없음.
- 색상 모드 **RGB**. CMYK로 저장하면 브라우저에서 색이 어긋나 보임.

### 지도 이미지에 존을 함께 그려 넣지 않는 방식 (현재 방식)

현재 지도 이미지는 **텍스트 라벨(① ~ ⑧)만 그려져 있는 배경-only 버전** 입니다. 각 존의 시각적 아이콘(그루터기, 미러월 등)은 별도 PNG 로 지도 위에 얹혀 렌더링됩니다. 이 방식의 장점:

- 아이콘만 교체하면 즉시 반영됨 (지도 배경 재작업 불필요)
- 인터랙션(글로우, 선택, 페이드) 이 아이콘 오버레이에만 적용되어 UI 반응 명확
- 지도 배경은 라벨·경로만 담고 있어 재활용성 높음

지도를 새로 그릴 때도 이 방식(배경 = 라벨·경로만, 아이콘 = 별도 파일) 을 유지하시길 권장합니다.

## 2. 지도 위 존 아이콘 (8개)

**파일:** `public/icons/zone1.png` ~ `public/icons/zone8.png`
**형식:** **PNG 투명 배경 (RGBA)** — 필수
**정확한 크기:** **800 × 800 px (모두 동일)**
**정확한 비율:** **1 : 1 (정사각형)**

### 스펙이 통일된 이유

지도 리뉴얼 시 모든 아이콘을 **동일한 정사각형 규격**으로 통일했습니다. 존별로 다른 비율을 관리할 필요가 없어져서 디자인·교체 작업이 크게 단순해졌어요.

### 존별 아이콘 내용 (2026-07-07 확정본)

| Zone | 아이콘 파일 | 그려진 요소 | 비고 |
| --- | --- | --- | --- |
| 1 | `zone1.png` | 문 모양 포털 (원형 아치) | 단일 요소 |
| 2 | `zone2.png` | **5개 그루터기 그룹** (군집 배치) | 그루핑 아이콘 |
| 3 | `zone3.png` | 2개 버섯 모양 | 단일 그룹 |
| 4 | `zone4.png` | 큰 그루터기 + 잎사귀 | 단일 요소 |
| 5 | `zone5.png` | **3개 미러월 지그재그** (상단·중앙·하단) | 그루핑 아이콘 |
| 6 | `zone6.png` | LED 벽 (5개 달 배치) | 단일 요소 |
| 7 | `zone7.png` | 원형 데크 + 파도 이펙트 | 단일 요소 |
| 8 | `zone8.png` | 빛의 파동 (물결·별) | 단일 요소 |

**그루핑 아이콘 (Zone 2, 5) 재제작 시 주의:**
- 800×800 캔버스 안에 다중 요소를 배치
- 각 요소가 대략 200~300px 크기로, 균등한 간격으로 배치
- 캔버스 중심을 기준으로 대칭적/균형적 배치

### 아이콘 디자인 가이드

- **투명 PNG** — 배경이 무조건 투명 (RGBA). 코너 픽셀의 알파값이 0 이어야 함. 배경색이 있으면 지도 위에서 사각 박스처럼 도드라짐.
- **아트가 캔버스 중심** — 800×800 캔버스의 정중앙에 아트 배치. 오프셋이 있으면 지도 위 위치가 어긋남.
- **안전 영역(safe area)** — 캔버스 가장자리에서 **50~80px 여백** 을 두고 아트 배치. CSS 글로우 효과가 캔버스 끝에 잘리지 않게 하기 위함.
- **색상** — 어두운 밤 지도 배경 위에 얹히므로 채도 높거나 밝은 톤 유리. 완전한 검정은 배경에 묻혀 안 보임.
- **8개 아이콘의 시각적 무게감(크기감)이 서로 균형** 을 이뤄야 지도 전체가 안정적으로 보임. 어떤 아이콘만 훨씬 크거나 진하면 부자연스러움.

### 확정된 존별 위치 좌표 (참고용)

`src/data/zones.json` 안의 `mapPin` 값입니다. 아이콘만 교체할 때는 이 좌표를 건드릴 필요 없음:

| Zone | cx | cy | w | h |
| --- | --: | --: | --: | --: |
| 1 하슬라 포털 | 68% | 83% | 11% | 8.38% |
| 2 그루터기 숨결 | 54% | 80% | 11% | 8.38% |
| 3 거울 연못 | 67% | 72% | 10% | 7.62% |
| 4 다섯개의 달 | 50% | 67% | 13% | 9.90% |
| 5 달의 초상 | 58% | 57% | 18% | 13.71% |
| 6 인피니티 포레스트 | 39% | 35% | 12% | 9.14% |
| 7 달의 잔상 | 30% | 22% | 10% | 7.62% |
| 8 빛의 파동 | 14% | 12% | 11% | 8.38% |

**계산 규칙:** 지도가 1600×2100 이므로 `h = w × 0.7619` 여야 1:1 pixel square 로 표시됨. 좌표 수정 시 이 관계 유지.

### 아이콘 교체 방법 (담당자 셀프 가능 🟢)

GitHub 웹에서 파일만 교체:

1. https://github.com/shimyawn/hasla 접속 → 로그인
2. `public/icons/` 폴더로 이동
3. 교체할 파일 (예: `zone1.png`) 클릭 → 우측 상단 ⋯ → **Delete file** → 커밋
4. `public/icons/` 폴더로 돌아옴 → **Add file → Upload files**
5. **동일한 파일명** (`zone1.png`) 으로 새 이미지 업로드 → 커밋
6. 1~2분 후 https://hasla-gangneung.vercel.app/map 에서 반영 확인

**주의:**
- 파일명 정확히 일치 (`Zone1.png`, `zone_1.png` 등 변형 금지)
- 반드시 800×800 정사각형 유지
- 투명 배경 PNG (RGBA), JPG 로 저장하면 안 됨
- 아이콘 크기·위치를 바꾸려면 `src/data/zones.json` 의 `mapPin` 수정 필요 (개발자 협업)

### 흔한 실수

- ❌ **JPG로 저장** → 투명 배경이 흰색으로 렌더링됨
- ❌ **배경이 흰색·검정색** → 지도 위에서 사각형으로 도드라짐
- ❌ **크기가 800×800이 아님** → 지도 위 위치·크기가 어긋남
- ❌ **아트가 캔버스 한쪽으로 치우침** → 지도의 그림과 맞지 않음
- ❌ **너무 작은 원본(예: 200×200)** → 데스크톱 레티나에서 흐려짐
- ❌ **그루핑 아이콘을 단일 요소로 재제작** → Zone 2, 5 는 반드시 다중 요소 유지

## 3. 존 대표 이미지 × 8

**파일:** `public/images/zone1_main.jpg` … `zone8_main.png`
**형식:** PNG 또는 JPG (혼재 가능)
**정확한 비율:** **16 : 9 (1.7778)**
**권장 크기:** 1600 × 900 (또는 그 배수). 최소 1120 × 630.

### 현재 확장자 규칙

혼재되어 있음. 신규 제작 시 아래 규칙:

| 파일 | 확장자 이유 |
| --- | --- |
| `zone1_main.jpg`, `zone7_main.jpg` | 실사 사진 계열 → JPG |
| `zone2_main.png` ~ `zone6_main.png`, `zone8_main.png` | 일러스트·투명 활용 → PNG |

**확장자를 바꾸는 경우** (예: `zone1_main.jpg` → `zone1_main.png`) 는 반드시 개발자에게 알려주세요. 파일명이 코드 안 3~4곳에서 참조되어 있어 코드 수정이 필요합니다.

### 디자인 가이드

- **비율 필수** — 16:9. 이 비율을 벗어나면 존 상세 페이지에서 위·아래가 흰 여백으로 남거나 좌우가 잘림.
- **최소 해상도** — 1120px 폭 이상. 이보다 작으면 데스크톱 시청 시 흐릿함.
- **파일 용량** — 존별 500KB ~ 1.5MB 이내 권장. 2MB 초과 시 페이지 로딩이 눈에 띄게 느려짐.
- **JPG 저장 시** — 품질 80~85로 저장. 100은 용량만 커짐.
- **PNG 저장 시** — 투명이 정말 필요한 경우에만 PNG. 불투명 이미지라면 JPG가 3~5배 가볍습니다.
- **텍스트/문구 삽입 지양** — 존 페이지에서는 이미지 위에 별도로 제목·설명 텍스트가 얹혀 표시됩니다. 이미지에 텍스트를 넣으면 다국어 대응이 안 되고 중복 노출됨.

## 4. 로고 3종 (스플래시·헤더)

로고는 **3장이 스플래시 애니메이션에서 한 세트로 동작** 합니다. 한 장만 교체하면 스플래시가 어색해지니 반드시 셋을 함께 제작·교체하세요.

### 4-1. 스플래시 컬러 로고

**파일:** `public/images/logo_color.png`
**용도:** 스플래시에서 뒤에서 떠오르는 컬러 로고 (문라이즈 효과)
**형식:** PNG 투명 (RGBA)
**정확한 비율:** **3 : 1**
**권장 크기:** 3000 × 1000

### 4-2. 스플래시 실루엣 로고

**파일:** `public/images/logo_black.png`
**용도:** 스플래시에서 앞쪽에서 아래로 내려가며 사라지는 실루엣 로고
**형식:** PNG 투명 (RGBA), 완전한 검정 실루엣
**정확한 비율:** **3 : 1**
**권장 크기:** 1500 × 500 이상

### 4-3. 헤더(상단바) 로고

**파일:** `public/images/logo_full.png`
**용도:** 상단 헤더바 로고 (모든 페이지 상단)
**형식:** PNG 투명 (RGBA)
**정확한 크기:** **1600 × 534**
**정확한 비율:** **3 : 1**

### 3종 로고 공통 규칙

- **완전히 같은 비율(3:1) 로 제작** — 스플래시 애니메이션에서 컬러/실루엣이 정확히 겹쳐야 자연스러움
- **워드마크만 포함** — 심볼+워드마크 조합인 현재 구조 유지 권장
- **컬러 로고와 실루엣 로고의 아트 위치가 정확히 일치** — 오프셋이 다르면 문라이즈 효과에서 튀어 보임

## 5. 티저 영상

**파일:** `public/videos/teaser.mp4`
**용도:** About 페이지의 티저 섹션
**형식:** MP4 (H.264 코덱, AAC 오디오)
**권장 규격:**
- 세로 영상 **9:16 (예: 1080×1920)** 또는 4:5 (예: 1080×1350)
- 길이 **30~60초** 이내
- 파일 용량 **10MB 이하** 권장. 최대 20MB 이내.
- 프레임레이트 30fps 또는 24fps

### 주의

- **iOS Safari에서 음성이 있는 영상은 자동 재생되지 않습니다** — 관람객이 재생 버튼을 눌러야 소리가 나옴. 첫 3~5초는 소리 없이 봐도 뭔지 알 수 있는 편집이 유리.
- **자막(캡션) 필요 시** — 영상에 직접 태워야 함. 사이트 자체에서 캡션 트랙(WebVTT)을 지원하지 않음.
- **썸네일** — MP4의 첫 프레임이 자동으로 썸네일로 사용됨. 첫 프레임을 정지 화면으로 예쁘게 뽑아주세요.

## 6. SNS 공유 미리보기 이미지 (Open Graph)

**파일:** `public/og.png` ✅ 이제 파일 하나만 교체하면 반영됩니다
**형식:** PNG
**정확한 크기:** **1200 × 630 px** (Facebook·카카오톡·X 표준)
**정확한 비율:** **1.905 : 1**

### 교체 방법 (담당자 셀프 가능 · 🟢)

1. GitHub 저장소 → `public/og.png` 선택
2. 우측 상단 ⋯ → **Delete file** → 커밋
3. `public/` 폴더로 돌아와 **Add file → Upload files** → 새 `og.png` 업로드 → 커밋

**주의사항**
- 카톡·인스타에서 공유 미리보기는 **캐시가 오래 유지**됨. 새 이미지 반영 확인은 https://developers.facebook.com/tools/debug/ 에서 URL 넣고 "Scrape Again" 하면 즉시 새 이미지 확인 가능.
- 텍스트는 화면 중앙 60% 안에 배치 — 미리보기 크롭에서 잘리지 않도록.

### 디자인 가이드

- 어두운 배경 + 브랜드 컬러 그라디언트가 어울림
- 워드마크(하슬라) + 부제(경포 환상의 호수) + 슬로건 조합 권장
- 텍스트 크기: 미리보기 썸네일(작은 사이즈)에서도 읽히도록 크게

## 8. 파일 제출 형식 & 명명 규칙

### 폴더 구조로 정리해서 주세요

```
hasla-design-YYMMDD/
├── 01_map/
│   └── map.jpg (1600 × 2100)
├── 02_zone_icons/
│   ├── zone1.png (800 × 800)
│   ├── zone2.png (800 × 800)
│   └── … zone8.png (800 × 800)
├── 03_zone_main/
│   ├── zone1_main.jpg (1600 × 900)
│   ├── zone2_main.png (1600 × 900)
│   └── … zone8_main.png (1600 × 900)
├── 04_logo/
│   ├── logo_full.png (1600 × 534)
│   ├── logo_color.png (3000 × 1000)
│   └── logo_black.png (1500 × 500)
├── 05_og/
│   └── og.png (1200 × 630)
├── 06_video/
│   └── teaser.mp4 (9:16 세로)
└── 07_source/  ← 선택. AI·PSD 원본을 참고용으로
```

### 명명 규칙

- 파일명은 **정확히** 위 표의 이름과 일치. `Zone1.png`, `zone_1.png`, `zone1-main.jpg` 같은 변형 금지.
- 공백·한글·괄호·물음표·다중 점(`.`) 금지.
- **파일명이 코드 안에서 참조되므로, 한 글자만 달라도 이미지가 안 뜹니다.**

### 색상 프로파일

- **RGB (sRGB) 로 저장** — 웹 표준. CMYK로 저장하면 브라우저에서 색이 어긋남.
- Photoshop에서 **파일 → 웹용으로 저장** 기능 활용 시 자동으로 sRGB로 변환됨.

## 10. 자주 묻는 질문

**Q. AI 파일로만 넘겨도 되나요?**
- 아뇨. 웹에 실제로 올릴 파일은 반드시 PNG/JPG로 export해서 함께 넘겨주세요. AI는 참고 원본으로만 유효합니다.

**Q. 아이콘을 800×800 이 아닌 다른 크기(예: 1024×1024)로 만들어도 되나요?**
- 됩니다. **정사각형(1:1) 비율** 만 정확하면 크기는 512 이상 어느 배수든 무방. 다만 8개 아이콘의 크기는 서로 같아야 합니다 (모두 800 또는 모두 1024).

**Q. 지도를 다른 비율(예: 1600×2400) 로 바꾸면 안 되나요?**
- 바꿀 수 있지만 개발자 협업 필수. 코드에 `aspect-[1600/2100]` 이 하드코딩되어 있어 이 값을 새 비율에 맞춰 수정해야 하며, 모든 mapPin 좌표를 재조정해야 합니다. 미리 알려주세요.

**Q. Retina(고해상도)를 위해 2x, 3x 파일도 따로 만들어야 하나요?**
- 아뇨. 단일 파일을 크게(권장 사이즈의 1.5~2배) 만들어주시면 Next.js가 자동으로 반응형 이미지를 생성합니다. 파일 여러 벌 준비할 필요 없음.

**Q. 시안(디자인 mockup) 확인은 어디서?**
- 배포 전 미리보기는 개발자에게 요청. GitHub에서 Pull Request를 만들면 Vercel이 자동으로 임시 URL을 발급하여 실제 사이트와 동일한 환경에서 확인 가능합니다.
